
## 9/4 深夜：抽屉交互攻坚终局

- **三个 Compose 大坑（实测实锤）**：
  1. `clickable(enabled=false)` 仍吞 tap —— 全屏透明 scrim 即使 disabled 也让全部点击失效 → scrim 必须 `if (presenting) { }` 条件组合，绝不能常驻 disabled。
  2. `graphicsLayer { translationX }` 平移**不移动 hit 区域** —— 关闭态抽屉（屏外视觉）仍挡左屏点击 → 移动中的面板用 `Modifier.offset {}`（layout 移动、hit 跟随），只有内容平移（child）用 graphicsLayer。
  3. 全屏 `pointerInput(detectHorizontalDragGestures)` 与子 clickable 冲突，tap 全灭（本 Compose 版本）→ 手写 awaitEachGesture 检测器：tap 放行（不消费 up），水平 slop 后才 consume；且 **edgeOnly 模式**（down.x > 24dp 直接 return）—— 从左缘拖出抽屉，零点击干扰。
- 输入栏 ime：edge-to-edge 下必须手动 `.windowInsetsPadding(WindowInsets.ime)` + navigationBars，否则键盘遮输入栏。
- settle 动画：spring(dampingRatio=1, StiffnessMedium) 带初速衔接手指（无速度突跳）。
- 调试手段：`adb shell uiautomator dump` 拿按钮真实 bounds；`logcat -d | grep TAG` 验证点击链路；PNG 像素分析（stdlib zlib+struct 解 PNG，Pillow 不可用）。
- 菜单图标：用户要**递进三横线**（20/13/6.5 圆角条，drawable/drawer_menu_list.xml）——非原项目 list.svg（两条），用户明确要求三条递进。
