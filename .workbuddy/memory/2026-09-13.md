## 键盘抬起顶起对话内容（提交 `695c887`，门禁 5/5 绿，用户真机确认「没有问题」）

**用户点名的需求**：「输入框抬起可以抬起对话内容」+「你看看原项目是不是有这个功能」→ **原项目有**，我们只缺半边。

**原项目做法**
- `home_mobile_layout.dart:123` `Scaffold(resizeToAvoidBottomInset: true)`
- `home_page.dart:763-771` `didChangeMetrics`：`nextInset > _lastViewInsetBottom + 0.5` 且是移动端 → `scrollCtrl.pinBottomDuringViewportResizeIfNeeded()`
- `scroll_controller.dart:312-321`：`isNearBottom(24)` 才 `positionAtBottomOnNextLayout()`；注释明确「必须在新视口尺寸布局**之前**请求，否则旧的像素偏移会以高于新底部一帧的方式绘制」
- `home_page.dart:739-742` post-frame 里用真实 inset 播种 `_lastViewInsetBottom`（否则「启动时键盘已开」会被当成一次抬起）

**我们这边的缺口**：布局半边本来就有（输入栏 `windowInsetsPadding(WindowInsets.ime.union(navigationBars))` + 列表 `weight(1f)` ⇒ 视口随键盘缩小），**缺的是「钉底」**。滚动位置是按像素记的，视口一矮 `maxScrollExtent` 就变大 → 用户正在看的最新一条被压到输入栏后面。

**实现**
- `app/.../ui/chat/ChatViewportFollow.kt`：纯函数 `shouldPinTimelineOnImeRise(previous, next, pointerDown, following)`（只在 inset 变大时钉 / 手指在屏上绝不钉 / 只在 following 时钉）。
- `HomeScreen.ChatContent`：读 `WindowInsets.ime.getBottom(scrollDensity)`，`LaunchedEffect(imeBottomPx)` 里判 → `scrollTimelineToBottom()`；`lastImeBottomPx` 初值取当前 inset（对齐原版播种）。
- 收起键盘不用管：视口长回去后 LazyList 自己把 `pixels` 夹回新的 `maxScrollExtent`，仍贴底。

**⚠️ 关键坑（Compose 时机）**：原版能在 `didChangeMetrics` 里判 `isNearBottom(24)`，是因为该回调**在新视口布局之前**。Compose 不行 —— `LaunchedEffect` 的协程体（`AndroidUiDispatcher`）可能在本帧 layout **之后**才跑，那时 `layoutInfo` 已是缩小后的几何，`tailAtBottom(24)` 必然为假 ⇒ **功能静默失效（不报错、就是不动）**。改用**同源的 `following`**（=「尾巴在底部且用户没接管」，由位置判定维护）当判据，与 effect 运行时机无关。
→ **推广：凡是「原版靠某个「布局前」回调读几何」的行为，搬到 Compose 时都不能用 effect + layoutInfo 复刻**；要找同一份状态在组合里的等价表达。

**测试与验证**：`ChatViewportFollowTest` 6 例（抬起钉 / 同一 inset 不钉 / 收起不钉 / 手指在屏上不钉 / 读历史不钉 / inset 继续变大再钉）。真机验证（PKB110）：时间线在底部时点输入框，内容整体上移 —— `9,420 tokens` 那行从 y=2025 → y=252，最后一条回复完整可见在输入栏上方；用户截图确认「没有问题」。

**squeeze-in**：PORTING.md §4 的条目号与用户后加的条目**撞号**（两个 `28.`）——我把自己那条挪到末尾改成 `43.`，并校验 §4 编号 1..43 连续无重。**教训：往 PORTING.md §4 追加条目时要先查当前最大号与重复号，别默认接着自己上次的号写。**
