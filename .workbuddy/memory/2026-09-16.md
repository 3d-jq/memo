## 语音这部分：照原项目补完（用户 2026-09-16「按照原项目改吧」，已装机）
**①「听测试」真播 + 出胶囊**：
- 上游两个入口：`tts.speakSystem(text)`（→ `_speakQueued(text, flush)`，networkService=null）与 `tts.speakWithNetworkService(service, text)`，**都走同一条播放队列**，所以测试播放必然出悬浮胶囊。
- 落地：`TtsSessionOverride`（sealed：`System` / `Service(options)`）+ **纯函数 `resolveSessionService(override, selectedId, services)`**（判优先级、可单测）挂在 `SwitchableTtsEngine.selectedNetworkOptions()`；`TtsPlayer.speakSystem/speakWithService`；普通 `speak()` 会**清掉覆盖**回到「按选中项」。两个测试按钮（系统行 + provider 行，后者原来是空实现）都改走管线。
**② 系统语音**半速播放**（用户「在对话界面点击 速度这么慢」的真因）**：
- 内部 rate 轴是从 `flutter_tts` 抄的：那个包 **0.5 才是正常语速**（`tts_provider.dart:79` 注释原文），所以上游存 0.5、显示 ×2。网络引擎用 `mediaPlayerSpeed(rate)=rate*2` 还原了，**但 `SystemTtsEngine` 把 0.5 原样传给 Android `setSpeechRate`（1.0 才是正常）→ 一律半速**。
- 修：新增 `TtsPlaybackSpeed.toAndroidSpeechRate(rate) = rate*2`（TtsPlayback.kt），系统引擎改用它；测试把它与 `mediaPlayerSpeed` 钉在一起，防两条路再次跑偏。
**教训（很值钱）**：跨框架移植 rate/速度/透明度这类**轴制不同的参数**，必须逐项核对「对方 API 的正常值是多少」——上游注释里其实写明了 `0.5 is normal`，照抄数值就错。
