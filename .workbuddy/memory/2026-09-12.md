## 本批次踩到的两个真 bug（测试抓到的，务必记住）

1. **SigV4 的百分号编码必须大写十六进制**。`awsEncode` 一开始用了小写（`%2f`/`%2a`）——签名照样能算出来，但 S3 会回 `SignatureDoesNotMatch`。
   注意方向相反：**签名串本身是十六进制小写**（Authorization 里那串）。Dart 的 `Uri.encodeComponent` 与 Java 的 `URLEncoder` 都是大写。
   → 用 AWS 官方向量锁死（`GET /test.txt` + `Range: bytes=0-9`，20130524T000000Z → `f0e8b8…6bdb41`），这是唯一能在没有 bucket 的情况下证明 canonical request 逐字节正确的办法。
2. **签名里的 Host 必须省略默认端口**（443/80），因为 HTTP 客户端实际发出的 Host 就是不带端口的；带上就签名不匹配。
   另：`host` 与 `content-length` **不要手动塞进 OkHttp 请求头**（OkHttp 自己按 URL/body 生成，重复写 S3 直接拒），但签名里必须有这两个。

## 其它两条容易踩的

- **`ApiResponse` 要读完整 body**（分页 listing 是整份 XML）；只有**流式**上传/下载的错误路径才用 `peekBody`（peek 不消费 body）。
- **XML 解析测试必须放 app 模块（Robolectric）**：`core:data` 无 Robolectric，纯 JUnit 里 `XmlPullParserFactory.newInstance()` 是 stub（`not mocked`）。惯例＝core:data 放纯逻辑、app 放 Robolectric，跨模块被测 API 需 public（同 `WebDavClient.parseMultistatus`）。
