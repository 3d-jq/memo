## 用户 8 条反馈批次 —— 第一批已修（已装机）
三条拿到**真机证据**的根因 + 修复：

- **聊天记录存储一直「统计中」**：`SettingsScreen` 的摘要自己写了一遍遍历（口径还和存储页不一致），而真机 `filesDir` 共 34,615 个文件、其中 `workspaces` 占 34,342（99.2%）——全是沙箱 proot 的 Linux rootfs。逐文件 stat 要十几秒 → 永远填不上数字。修：① `StorageUsage.computeReport` 新增 `skip` 参数，跳过 `workspaces/<助手 id>/linux` 子树（判据 `isWorkspaceRootfs`，只认这一层）；② 摘要改用与存储页**同一份** `computeReport`（上游也是同一个 service）；③ 失败落地成「—」，不再无限转圈。实测跳过后面只剩 **273** 个文件。
- **打开加载数据的界面就卡顿**：`AppContainer.providerConfig()` 每次都「新建 DAO → 查库 → 解 JSON」，零缓存，而它在组合期高频调用（单次请求组装就打 4 次）。修：新增 `ProviderConfigCache`（core:data），读走缓存；失效挂在 `PayloadEntityDao` 的 upsert/delete/replaceAll（`table == "provider_rows"` 时整表失效）——工程内没有绕过 DAO 的裸 SQL 写 provider_rows，备份恢复也走 replaceAll，所以失效面完整。
- **消息生成触觉没生效**：原来只挂在发送按钮的 `onSend` 上（回车发送/建议气泡/重新生成全漏）。上游是 ViewModel 回调（`home_view_model.dart:185` 声明、`:423` 发送、`:495` 重新生成前触发）。修：`ChatViewModel.onHapticFeedback` + send/regenerate 各触发一次，HomeScreen 用 `SideEffect` 注入（`chatHaptics.onGenerate` + `Haptics.light(chatView)`），并删掉两处内联触发防止震两次。
- 测试：`ProviderConfigCacheTest`(4) + `ProviderConfigCacheInvalidationTest`(4) + `ChatGenerationHapticsTest`(3) + `StorageUsageWorkspaceScanTest`(3)，全量单测 + lint + 打包绿。

### 血泪
- **KDoc 里写 `/**` 会截断整个文件**：Kotlin 支持嵌套块注释，注释里出现 `/*`（我写了 `workspaces/<id>/linux/**`）会开一个永不闭合的嵌套注释 → 报 `Unclosed comment` + 一堆莫名其妙的 Unresolved reference。注释里提路径时别写 `/**`。

## 用户 8 条反馈批次 —— 第二批（返回跳级 + 返回键触感，已装机）
- **二级界面返回跳级（用户点名「日志那些界面」）**：根因是日志页的文件/快照/详情页是**同屏 overlay**（不是导航目的地，只是叠在列表上的一层 composable）——自己的返回箭头能回列表，但**系统返回键没人拦** → 落回 NavHost → 直接 pop 掉整个日志路由 → 回主设置页。修：`BackHandler { onClose() }` 放进 `LogViewerScreen.OverlayScaffold`（改 internal），5 处同款二级页一次覆盖。**判据：Dialog 形态的覆盖层（图片查看器）不用加，系统返回由 Dialog 自己收**；新写「同屏二级页」必须自带 BackHandler（先例还有 `WorkspaceDetailScreen:222`）。
- **返回箭头没有点击阴影**：`MemoTopBar`/`WorldBookSheet`/`IconActionButton` 都有按压反馈（`IosIconButton`：按压变色+缩放），但 `StatsScreen` 与 `MemoryTraceScreen` 用的是 M3 `IconButton` —— 而**本工程全局关掉了 ripple**，所以那里点下去毫无反馈。修：两处换成 `IosIconButton`（参数照 MemoTopBar：size 22 / contentPadding 0 / minSize 44）。
- 测试：`LogOverlayBackTest`（Robolectric + `createAndroidComposeRule<ComponentActivity>` + `onBackPressedDispatcher.onBackPressed()` 派发系统返回）。这套「派发真实返回键」的写法是本项目第一次用，以后测返回行为照它写。

## 用户 8 条反馈批次 —— 第三批（工作区 + 双震，已装机）
- **「管理工作区」点了没反应**：链路是 「+」面板 → `WorkspaceSelectorSheet` → `HomeScreen(onOpenManage→onOpenWorkspaces)` → `MainActivity`，而 **`home` 路由根本没传 `onOpenWorkspaces`**，参数 `= {}` 默认值把点击吞了。修：路由补传 + **去掉该参数默认值**（以后再漏传直接编译不过；顺手暴露并修了两处测试调用点）。**教训：导航回调类参数不要给 `= {}` 默认值**——漏接线时静默失效，用户点半天没反应还查不出来。
- **看工作结果**（用户要求）：选择面板每行加「查看文件」`IosIconButton` → 新的 `WorkspaceFilesSheet`（Memo sheet 外壳 `MemoSheetHandle` + 高度上限，内部直接复用详情页的 `FilesTab`，两处行样式天然一致）。该 sheet 只**浏览 + 文本预览**（`FileEditorSheet` 复用，editable=false）；导出/分享/删除仍走详情页，所以 `FilesTab` 新增 `showFileActions = false`（sheet 里菜单整颗不画，不会出现点了没反应的空菜单）。
- **抽屉收起震两下**：手势 settle 的 `onSettle` 里自己发了一次 `drawerPulse`，紧接着 `drawerOpen` 翻转又触发 `LaunchedEffect` 里的 `settleDrawer` 再发一次。上游 `onDrawerValueChanged`（home_page_controller:2364）是**越过 0.05/0.95 阈值发一次**。修：pulse 只留在 effect 里、且只在**状态真的翻转**时发（首帧不发、旋转改宽度不发）。
- 待跟进：若**点会话行**回主对话仍觉两下，那是「行 light + 抽屉 pulse」的组合（上游也有），可以按用户偏好去掉其中一个。
