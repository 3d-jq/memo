## Agnes（用户自配的生成服务）排障结论 —— 全网实测（key 只测不存）

- **真根因**：**Agnes 的 key 与节点是代际绑定的**。同一把 key：`https://api.agnes-ai.cn/v1` → 401「无效的令牌」；`https://apihub.agnes-ai.com/v1` → 200，12 个模型正常。用户把 base URL 换成**国际节点**后测试即通过。
- **鉴权同一套**：`/models`、`/images/generations`、`/videos` 三处的 401 文案一致（不带 key → 「未提供令牌」；乱填 key → 「无效的令牌」）⇒ /models 的结果可代表生成端点会不会被拒（不必另做生成探测）。
- **响应形状（真实）**：`POST {base}/images/generations` 200 返回 `data[0] = {url, b64_json:"", revised_prompt}` —— **b64 是空串、真图在 url**；我们 `GenerationHttp.str()` 跳过空串 → 回落到下载 url ✓（已补回归测试 `an empty b64 field falls back to the url`）。
- **size 不是必需**（用户猜「要尺寸才可以行」不成立）：不带 size 也 200 出图；带 `1024x1024` 同样 200。
- **模型名**（12 个）：图 `agnes-image-2.5-flash` / `-2.1-flash` / `-2.0-flash`；视频 `agnes-video-2.5-flash` / `agnes-video-2.5` / `agnes-video-v2.0`；文本 `agnes-3.0-flash` 等。
- **「无可用渠道」类报错**：`{"code":"model_not_found","message":"分组 default 下模型 X 无可用渠道(distributor)"}` = 该**节点/账号分组**没有这个模型的渠道（不是模型名写错、也不是 key 问题）。实测同一把国际 key 在国际节点上三个图片模型**都能出图** ⇒ 混用「国内 key + 国际端点」（或反之）会走到渠道不匹配的分组。
